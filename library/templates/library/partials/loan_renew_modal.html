{% load i18n %} {% comment %} Extend a loan, in a dialog, with the date the librarian chooses. This is the one place where the behaviour changed rather than moved. Renew used to compute the new due date from policy and never ask - so a loan could only ever be extended by exactly the policy period, and a librarian who needed a particular day could not have one. Now there is a calendar field: * `min` is today, or the current due date when that is later. A renewal moves the date forward; offering a past day would let somebody mark a book overdue that is not. * it opens on the policy's own date, so the common case is still one click and nothing has to be typed. * the view re-checks all of it, because `min` on an input is a courtesy to the person using it and not a rule. The renewal limit is unchanged and still enforced under a lock, so this cannot be used to get around it. Expected context: loan, new_due_date, error_message, renewals_used, renewal_limit, loan_period_days, earliest_due_date. {% endcomment %}
