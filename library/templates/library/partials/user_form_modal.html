{% load i18n %} {% comment %} Add / Edit User, as a dialog. One template for both, the way one template serves all six lookup dialogs. `editing` decides the title, the submit label and whether the password is required. The password field is required when creating and optional when editing, because on an edit "blank" means leave the existing one alone - there is no way to read it back to prefill, and clearing it would lock the account out. Only the roles the view offers appear here. SuperAdmin is not among them: that account is made by somebody with database access, deliberately, so it cannot be granted from a form however the request is shaped. The title is swapped out-of-band, so one dialog serves Add, Edit and Delete without the shell knowing which is inside it. Expected context: action, editing, error, username, full_name, role, roles, target_user. {% endcomment %}
