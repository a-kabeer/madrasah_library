Without HTMX the same form still works as an ordinary navigation. hx-include pulls the current sort, direction and page size out of #tableState, which the fragment re-renders on every swap — reading them from hidden fields here would send whatever was true when the page first loaded. `page` is deliberately not carried, so a new search starts at page 1. hx-disinherit keeps none of these attributes reaching anything nested. It matters in the other two modes, where the searchable dropdown inside the form makes its own hx-get to a different endpoint and must not push history or swap the results; it is set here too so all three forms stay identical in this respect. `partial` rides in the hx-get URL rather than hx-vals for the same reason, and because hx-vals is the one attribute hx-disinherit does not cover: HTMX merges it down from every ancestor, so the dropdown's own request would have carried it as well and come back with a table in it. {% endcomment %}
