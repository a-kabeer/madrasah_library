    {% comment %} Everything that changes on a search, filter, sort, page or page-size change lives in here, so those actions swap this fragment instead of reloading the page. The attributes are set once on the container and inherited by the links inside it, which is why the sort and paging links only need hx-get. hx-push-url keeps the address bar in step, so the state is still shareable and the back button still works. `partial` names the fragment the view should answer with; it travels in hx-vals so it exists only on these requests and never on a plain navigation. hx-indicator points at this container, which `.swap-busy` dims while a request is in flight.
