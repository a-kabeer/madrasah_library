{% load i18n %} {% comment %} One loan, in the dialog the row opens. This dialog IS the loan detail now - there is no page behind it. The `loan_detail` view serves this fragment, and a request without `?modal=1` redirects to the list, because several pages link to that URL and a stale link should still land somewhere. Four sections, because a loan is four different questions and a librarian usually has only one of them: what the loan is, which book it is, who has it, and who handled it. Flat rows of label/value are quicker to scan for that than prose. The footer is the way out to the two places worth going: the book and the borrower. Those used to be competing links inside the row, where any click had to be aimed; here the whole row opens the dialog and the dialog offers them plainly. Return and Renew are not repeated here. They stay in the row's Actions, which is where a librarian working through a shelf of returns expects them, and putting them in the dialog too would mean two paths to the same irreversible thing. Expected context: loan (with days_overdue set by the view). {% endcomment %} {% comment %} The title twice, once per dialog container: a loan row opens #globalModal and the links on the book, borrower, copy and dashboard pages open #formModal. htmx skips an out-of-band swap whose target is not on the page, so whichever dialog is showing gets its heading and the other line does nothing. {% endcomment %}
