{% load i18n %} {% comment %} English / اردو / العربية for the topbar. Beside the theme selector and built the same way - the Bootstrap dropdown the topbar already uses - but working differently underneath, and the difference is the point. A theme is applied by the browser, so that control changes the page itself and saves in the background. A language is applied by the *server*: the page in front of the reader is already rendered in the old one, so choosing a language has to fetch the page again. Each option is therefore a real form post, which is also what makes it work with no JavaScript at all. Two posts, depending on who is asking: * signed in -> `language_set`, which stores the choice on the account so it follows them to another machine, and redirects back to the page they were on. * not signed in -> Django's own `set_language`, which writes the session and a cookie. The login page and the public catalogue both need this, and neither has an account to store anything on. `next` carries the current page so the reader lands back where they were rather than at the dashboard. {% endcomment %} {% get_current_language as current_language %} {% get_available_languages as available_languages %}
