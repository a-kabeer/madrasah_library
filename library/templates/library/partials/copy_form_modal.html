{% load i18n %} {% comment %} Add / Edit Copy, in a dialog. One template for both, so the fields and their error slots cannot differ between adding a copy and editing one. `action` is where it posts; `copy` being set is what turns two of the fields from inputs into stated facts: * the copy code is printed on the book itself and quoted in past activity-log entries, so retyping it would leave the label, the record and the shelf disagreeing. Set once, read-only after. * the volume decides which book a past loan appears to have been for. A wrongly-filed copy is a delete-and-re-add, not an edit. Both are enforced in `validate_copy_details`, not by leaving the input out — the missing input is the courtesy, the validator is the rule. Location and Shelf are two dropdowns because a shelf belongs to a location: choosing the location narrows the shelves to the ones that actually exist there, so a copy cannot be filed somewhere it cannot be. The view re-checks the pair. Expected context: action, form_data, errors, error, copy, volume_name, selected_volume, volumes, locations, shelves, statuses, is_issued. {% endcomment %}
