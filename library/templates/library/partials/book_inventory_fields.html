{% load i18n %} {% comment %} The physical side of a new book: volumes, how many copies of each, and where they go. This is the part that saves the librarian walking Book -> Volume -> Copy -> Shelf by hand. It is deliberately plain markup: with JavaScript running, app.js shows one step at a time, keeps the copy rows in step with the volume rows, and reloads the Shelf list when the Location changes. Without it every section is simply visible at once and a single-volume book with a copy count still saves correctly — one long form rather than a broken one. Field names are read by `read_volume_rows` and `read_copy_plan`: volume_mode single | multiple volume_number \\ one pair per row, in the same order, so a row and its volume_title / copy count stay together copy_qty one per volume row copies_mode skip | add code_mode auto | manual copy_code one per copy, in volume order, only when code_mode=manual location \\ checked against each other on the server shelf / Expected context: inventory, locations, shelves, max_copies_per_volume, max_total_copies, id_prefix. {% endcomment %} {% comment %} ---------- Step 2: volumes ---------- {% endcomment %}
