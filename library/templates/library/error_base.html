{% extends "library/base.html" %} {% load i18n %} {% comment %} Shared layout for 403 / 404 / 500. Overrides `body` rather than `content`, so error pages inherit the head (theme resolution, branding colours, assets) without the application chrome. That is deliberate: a sidebar full of nav links is misleading on an error page, and on a 500 those pages may be broken too. Everything here must render with NO context, because Django's handlers differ: * 404 renders with `template.render(context, request)` * 403 renders with `template.render(request=request, context=...)` * 500 renders with `template.render()` — no request, so **no context processors run** and `branding` does not exist So `branding` is guarded everywhere below, `{% block title %}` is static text rather than the organisation name, and nothing here touches the database — a 500 is often caused by the database being unreachable in the first place. Child templates fill: error_code, error_icon, error_title, error_message. {% endcomment %} {% block body %}
